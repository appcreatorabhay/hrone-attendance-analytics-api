# REVIEW.md

The starter has several correctness, contract, performance, and concurrency defects.

| # | Where | What is wrong | How to notice | Fix |
|---|---|---|---|---|
| 1 | MongoClient setup | Connection defaults are hard-coded and client timezone handling is implicit. | Start with injected `MONGO_URI`/`MONGO_DB`; inspect BSON/API time conversions. | Read environment variables (environment overrides `.env`) and configure timezone-aware UTC datetimes. |
| 2 | `health()` | Always returns 200 without checking MongoDB. | Stop MongoDB and call `/health`. | Ping the database and return 503 when the ping fails. |
| 3 | Startup | No required indexes are created. | Inspect `getIndexes()` on both collections. | Create idempotent unique and query-supporting indexes at startup. |
| 4 | `compute_late_minutes()` | Uses naive/local timestamp assumptions and truncates the shift-start comparison incorrectly around the grace boundary. | For a 09:30 shift, test 09:40:00 and 09:40:01. | Convert the instant to IST, truncate to whole seconds first, apply the strict `> 10 minutes` condition, then floor elapsed minutes from the original shift start. |
| 5 | `compute_work_hours()` | Python `round()` uses ties-to-even, not the contract's half-up rounding. | Test durations exactly at a half-centesimal rounding boundary. | Use `Decimal` with `ROUND_HALF_UP` after computing elapsed seconds. |
| 6 | `compute_overtime()` | Does not apply the 30-minute minimum and always places shift end on the attendance date, failing overnight shifts. | Test 20 minutes overtime and a 22:00–06:00 shift. | Place shift end on the following date for overnight shifts and return overtime only when floored elapsed minutes are at least 30. |
| 7 | Pydantic request models | Missing contract validation for employee code, email, date/time formats, statuses, and epoch-millisecond values; invalid extra derived fields may be accepted/ignored inconsistently. | Send seconds instead of milliseconds, invalid statuses, malformed dates, or equal shift times. | Add constrained fields/validators; reject invalid inputs with 422 and never accept client-supplied derived fields. |
| 8 | `create_employee()` | Check-then-insert is race-prone; `created_at` is a naive local datetime; equal shift times are not rejected. | Send parallel requests with the same `emp_code`; create equal start/end shifts. | Enforce uniqueness with a database unique index, catch duplicate-key errors as 409, store UTC-aware server time, and validate shift times differ. |
| 9 | `list_employees()` | `skip = page * page_size` skips page 1; `total` ignores the department filter; ordering is not specified; page parameters have no bounds. | Request page 1 and filter by department. | Use `(page - 1) * page_size`, count the filtered query, sort by `emp_code`, and validate page/page_size. |
| 10 | `punch_in()` | Unknown employee causes an unhandled error; falsy `punched_at=0` is treated as omitted; timestamps use machine-local time; date is not derived in IST; timestamps are not truncated; status is not restricted; pre-check plus insert is race-prone; response leaks a generated `id`. | Test unknown employees, zero/invalid timestamps, non-IST host settings, invalid status, parallel duplicate punches, and inspect response fields. | Validate request, distinguish `None` from zero, convert epoch milliseconds to UTC then IST, truncate to seconds, derive overnight attendance date, rely on a unique `(emp_code,date)` index, catch duplicate-key errors as 409, and never return `_id`/`id`. |
| 11 | `list_attendance()` | Loads every matching document into Python, sorts in memory, and only then paginates; sort misses `emp_code` tie-breaker; it exposes `_id` as `id`; invalid date ranges/status/page sizes are not validated. | Seed many records, request a page, and inspect the response/order. | Validate filters, count the filtered query, use indexed MongoDB sort/skip/limit with `date` descending and `emp_code` ascending, and project/serialize only contract fields. |
| 12 | Missing `POST /attendance/punch-out` | No punch-out behavior, concurrency-safe close, 24-hour validation, or derived-field calculation. | Call the endpoint or send simultaneous punch-outs. | Implement atomic conditional update and the R3–R5 calculations. |
| 13 | Missing `PATCH /attendance/{emp_code}/{date}` | No validation, recomputation, change-only history, or concurrent-edit protection. | Correct a punch and inspect stored values/history; try a no-op patch. | Validate final state, recompute derived values, append one audit entry with only actual changes, and use a conditional update to prevent lost history. |
| 14 | Missing monthly employee analytics | No monthly totals, working-day calculation, or half-day handling. | Test a mid-month joiner, weekend records, leave, and open attendance. | Aggregate stored derived fields and calculate working days from `joined_on` under R7. |
| 15 | Missing department summary | No cross-collection aggregation or headcount inclusion for employees without logs. | Include a department employee with no attendance records. | Aggregate from employees and join monthly logs so zero-log employees count toward headcount. |
| 16 | Missing late leaderboard | No total-lateness aggregation, competition ranking, or tie-preserving limit. | Create ties at the requested cutoff. | Aggregate totals, join employee details, assign standard competition ranks, and filter by rank rather than array position. |
| 17 | Missing department trend | No date densification, daily headcount, rate, or rolling average. | Request a range containing weekends and days without attendance records. | Use a MongoDB aggregation with gap filling and a seven-row window restricted to the requested range. |
| 18 | Missing `/admin/explain/{endpoint}` | No explain endpoint to demonstrate index use. | Request explain for each supported endpoint. | Run `executionStats` explain on the endpoint's actual query/pipeline and return the raw explain document. |
| 19 | Serialization | BSON datetimes are returned directly or inconsistently, and the starter's `id` fields violate the API contract. | Inspect JSON responses for `created_at`, punch times, and history. | Convert every API instant, including nested history values, to integer epoch milliseconds and omit MongoDB `_id`. |

## Considered but not a defect

- `emp_code` is the employee identifier and attendance natural key is `(emp_code, date)`. MongoDB `_id` should remain internal; it must not be exposed as an API identifier.
- Missing `history` and `half_day` fields in older seeded attendance documents are valid legacy data and must be treated as `[]` and `false` respectively.
- A weekday with no attendance document is not equivalent to an `ABSENT` document. Analytics must distinguish these cases.
